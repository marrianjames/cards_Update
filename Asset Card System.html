Adaptive content cards for downloadable assets.

A modular card system for the partner portal. Every element except the title is optional — cards scale from a single download to multi‑file kits, with persistent footer actions and progressive disclosure of metadata.

01 / STATE

Collapsed

The default resting state. Strong hierarchy with a persistent footer that always exposes a primary download — secondary files are summarized as a counter.
  1. 1
    Logo Optional
    28px brand mark — partner/vendor identity. Hidden when not present; no placeholder.
  2. 2
    Status tags Optional
    Pastel pills, up to 3 visible. Semantic: success, info, neutral, warning, danger.
  3. 3
    Title Required
    Navy bold, 24px / 1.2. The only mandatory element of the card.
  4. 4
    Description preview Optional
    2‑line clamp in collapsed state. Reveals fully on expand.
  5. 5
    Footer summary Required
    Total package size + “+N files” counter when additional downloads exist.
  6. 6
    Primary download Required
    Always visible. Triggers the headline asset; never hidden behind expand.
  7. 7
    Expand control Conditional
    Chevron appears only when expandable content exists (long desc, metadata, or multi‑download).

04 / RULES

Key features

Four invariants the card system protects. Variants may add slots, but these behaviors hold across every variation above.
F.01

Persistent footer actions

The primary download is anchored to the footer in every state. Expanding the card never displaces it — users can always download without scrolling or hunting.

F.02

Progressive disclosure

Collapsed shows the headline; expanded reveals metadata and the file list. The chevron only appears when there's something hidden to expand to.

F.03

Scalable optional elements

Every slot above the footer — logo, tags, description, metadata — is independently optional. The title is the only required element. The card collapses gracefully around what's present.
